## Project summary

An app where a user paints a connector's mating face on a grid (housing, shell, pin, socket, key,
empty), enters details (pin count, plug/socket, later industry), and gets a ranked list of the
closest matches from a database of known connectors, with a similarity score.

## Scope

### MVP (version 1)
- Grid canvas (32x32) where you paint cells with a selected element type.
- Element types: housing, metal shell, pin, socket, key feature, empty.
- Details: pin count, plug or socket.
- Search button -> top 5 matches from the database, each with a similarity score.
- Database of about 20-30 common connectors, created by Claude from simple descriptions and
  corrected by Max.
- "Add to database" button so the database can grow.

### Not in MVP (later)
- Advanced search page (industry filter, weighting drawing vs details)
- Freehand drawing converted to a grid
- Photo upload / image matching
- Large-scale data import, user accounts, hosting online

## Decisions made (and why)

| Decision | Why |
|---|---|
| Drawing stored as a flat 32x32 grid, one label per cell | Searchable and comparable; raw pixels break when drawings shift or scale |
| Matching compares extracted features (outline, pin count/positions, keying), not pixels | Tolerates sloppy drawing |
| Grid painting (not freehand) for v1 | Simplest; maps directly to stored data |
| Starting database built by Claude (~20-30 connectors), grown via "Add" button | No clean free source exists; scraping is slow and legally grey |
| Python + Flask | Max already knows Python; Flask is the smallest web framework |
| SQLite | One file, nothing to install, plenty for this size |
| Shape stamps are shortcuts that paint cells (drag-to-size) | Stored data stays the same flat grid; full connector templates belong to the database, not the canvas |
| Database file is not committed; starting data will live in a committed seed file loaded into it | Keeps the repo clean and lets anyone rebuild the database |
| Search compares layers (outline, contacts, keys, element types) with a tolerant match, after cropping and stretching each drawing to fill the grid | Forgives wobbles, shifts and size differences; strokes stay 1 cell thick so outlines line up |
| Similarity: shape is the score; pin count and plug/socket are GUARDS that only lower it when both sides know them and disagree. Shape is calibrated so unrelated drawings read about 0% and identical 100%; the number of drawn contacts is part of the shape comparison. Tunables sit at the top of `matching.py` | First version added points for matching details and started every score at ~30%, so a 42-pin drawing scored 67-75% against a 24-pin connector. Max flagged it; now ~23% |
| Size (optional, mm, longest side of the face) and industry are used in the score as guards like pin count: within ~15% counts as the same size; "other"/"unknown" industry never counts against | Fixes look-alikes (3.5 mm vs 6.35 mm audio plug, RCA vs barrel jack). With the size known, every starter connector is found first (100%) |
| Advanced search = a collapsible panel on the same page: per detail Prefer (default) / Require / Ignore, results 5/10/20, "only checked drawings" | One page, no duplicate form; Require drops connectors that disagree but gives unknown values the benefit of the doubt |
| Saved connectors have a "checked" flag; starters load as unchecked drafts; saving an edit marks one checked; names are unique (ignoring case) | Lets Max work through the 35 starter drawings and correct them; stops accidental duplicates |
| Every drawing is centred on the grid when it is saved (`db.centre_rows`), and existing entries are centred at app start | Consistent thumbnails/loads; requested by Max |
| Starter connectors are generated by code (`seed_data.py`) and loaded with `py seed_db.py` | Readable, correctable, repeatable; no copyright/scraping issues |
| Plain HTML/JavaScript canvas, no front-end framework | Fewer moving parts for a beginner |

## Hard problems (raised early)

1. Storing drawings so they can be compared -> grid + extracted features (above).
2. Source of connector data -> hand-built seed set, then user-contributed.
3. Matching quality will need tuning against real examples; expect iteration.

## Known limitations

- Sizes and drawings of the starter connectors are approximations from general knowledge, not
  manufacturer drawings (35 drafts to check; the app shows how many remain).
- A size must be entered by the user to separate look-alikes; the drawing alone cannot tell sizes apart
  because every drawing is stretched to fill the grid.
- Drawing contacts with a big brush inflates the "number of contacts drawn" the search compares
  (use brush size 1 or the pin-pattern stamps for pins).
- Search reads every connector each time (drawings are cached in memory). Fine for hundreds;
  revisit if the database reaches thousands.
- Page and JavaScript are tested by browser runs and a static page check (`tests/test_page.py`),
  not by automated browser tests.
